## 調べて分かったこと

- **MinIO のイメージ（`minio/minio`・`minio/mc`）は、Docker Hub でも Quay でも取得できない（401）。**
  この VM に残る `quay.io/minio/minio:RELEASE.2024-12-18T13-15-44Z` だけで動いている。控えを VM の `/home/ubuntu/` に tar で書き出した
- ユーザーが選んだ案 (a)「`values.yaml` から `resources` を外す」は、そのままでは Chart の既定値 `requests.memory: 16Gi` になり、Pod が `Insufficient memory` で `Pending` になる（実際に確かめた）。
  そのため `requests` は残し、`limits` だけを v1 と v2 の差にした
- Chart の既定値ではユーザー作成の Job が `quay.io/minio/mc` を使う。`users: []` にすると Job が作られず、Release は `deployed` になった
- k3s（ノード 1 台）は etcd ではなく SQLite を使い、Secret は平文で入っている。`stringData` は `last-applied-configuration` にも平文で残る
- `ReadWriteOnce` はノード単位で、同じノードなら別の Pod も同じ PVC をマウントできた
- `multipass mount` は登録されているのに中身が空だった。`multipass transfer -r` で代用した
- learn5 のビルド中にディスク使用率が 85% を超え、kubelet が未使用のイメージ（`minio/minio:latest`、`minio/mc` など）を消した。`docker builder prune -af` で 59% に戻した
- 旧 README の誤り: learn5 の `hello.txt` は 30 バイト（旧 31）、learn2 の `enth0` は `enp0s1`、SSD の名前は `SSD-PGU3`
- 公式 nginx イメージは起動時に `/etc/nginx/templates/*.template` を envsubst で展開する（learn1）
