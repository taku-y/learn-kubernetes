## 調べて分かったこと

- RustFS は Apache-2.0。最新は `1.0.1`（2026-10-03）。Docker Hub の `rustfs/rustfs:1.0.1` は匿名で取得でき、arm64 もある
- Helm chart は `https://charts.rustfs.com` の `rustfs` `1.0.1`。既定は distributed（Pod 4 つ）
- **RustFS は NFS 上での運用を想定していない。**起動時に `Unsupported filesystem type detected ... (NFS)` を WARN で出す（既定は警告だけ）
- **この VM の NFS（`/mnt/ssd`）では、ファイルのロックが使えない。**`lockf`・`flock` が `No locks available`（errno 37）。
  RustFS は自己修復（heal）の途中経過を保存できないが、S3 の読み書きは通った
- RustFS は、既にあるバケットへの CreateBucket に成功を返す。MinIO では 409 で learn5 の Job が失敗していた
- Chart は既定の認証情報 `rustfsadmin` を拒んで展開を止める。Ingress が既定で有効。PVC に `helm.sh/resource-policy: keep` が付き、uninstall しても残る
- Chart の Deployment は `maxSurge: 0` で、upgrade では古い Pod を先に止める。手書きの Deployment（既定の RollingUpdate）では新旧の Pod が数秒間同時に動いた
- `multipass transfer -r` は上書きだけで、Mac 側で改名・削除したファイルは VM に残る
- 詳細と URL は [notes.md](../notes.md#rustfsminio-の代わり)
